# 桌面侧边栏：项目与工作目录分组

Status: implemented

代码任务01–08已完成并通过独立合并，集成分支 `desktop-directory-groups`，最终提交 `35f58e5db0`。此状态表示实现完成，不代表全部实机验收通过；原生选择器、桌面重启、性能等未验证项及自动化结果见 [acceptance.md](acceptance.md)。

## Problem Statement

桌面侧边栏的平铺会话列表难以体现项目和目录归属。现有项目视图以 Git 项目为中心，打开仓库子目录以及通过 Local 创建会话时可能重新选择仓库根目录，不适合 Maven 等多模块仓库。

用户需要在独立子模块中开展工作，直接定位模块内文件，并能同时管理同仓库多个模块的会话。仅增加分组外观不足以解决实际工作目录被改写的问题。

## Solution

保留原有平铺视图，新增支持按工作目录或按项目分组的侧边栏，优先使用目录视图。用户可以主动添加工作目录、筛选会话，并从目录入口创建实际位于该目录的会话。

工作目录与 Git 项目身份分开：文件浏览、工具默认操作和 `@` 文件候选搜索以所选工作目录为起点，Git 继续识别所属仓库，跨目录访问沿用现有权限。

## User Stories

1. 作为多模块项目开发者，我希望添加仓库中的具体子目录，以便在独立模块中开展工作。
2. 作为开发者，我希望打开子目录后保留实际选择的路径，以便新会话不会切回仓库根目录。
3. 作为开发者，我希望按工作目录查看会话，以便直接找到模块对应的历史。
4. 作为开发者，我希望按项目查看工作目录及其会话，以便掌握整个仓库中的工作。
5. 作为开发者，我希望保留平铺视图，以便继续使用原有浏览方式。
6. 作为开发者，我希望新分组样式优先使用目录视图，以便快速进入子模块。
7. 作为开发者，我希望同名目录附带项目或路径提示，以便区分不同位置。
8. 作为开发者，我希望添加没有 Git 的普通目录，以便管理非仓库工作。
9. 作为开发者，我希望使用系统文件夹选择器添加目录，以便选择任意可用文件夹。
10. 作为开发者，我希望从已知项目中浏览并选择子目录，以便方便地添加模块。
11. 作为开发者，我希望添加前看到完整路径，以便确认实际工作位置。
12. 作为开发者，我希望添加空目录后仍保留入口，以便稍后直接创建会话。
13. 作为开发者，我希望只添加主动选择的目录，以便侧边栏不会自动填满所有 Maven 模块。
14. 作为开发者，我希望点击目录旁的“＋”就在该目录创建会话，以便创建位置明确。
15. 作为开发者，我希望点击项目旁的“＋”先选择项目下的工作目录，以便避免误用根目录。
16. 作为开发者，我希望全局新建优先沿用当前会话目录，以便连续处理同一模块的任务。
17. 作为开发者，我希望无当前会话时沿用上次使用的目录，以便减少重复选择。
18. 作为首次使用的开发者，我希望没有默认目录时先选择目录，以便明确工作位置。
19. 作为开发者，我希望发送首条消息前能查看并修改目录，以便纠正创建位置。
20. 作为开发者，我希望 `@` 默认仅搜索当前工作目录下的文件和目录，以便快速定位模块文件。
21. 作为开发者，我希望文件浏览和工具默认操作与会话工作目录一致，以便避免在错误位置工作。
22. 作为开发者，我希望保留外层 Git 仓库识别，以便继续查看分支和差异。
23. 作为开发者，我希望按现有权限读取父级配置或兄弟模块，以便处理公共依赖和跨模块任务。
24. 作为开发者，我希望历史会话按已记录的工作目录展示，以便保持真实归属。
25. 作为开发者，我希望尚未添加的历史会话目录自动展示，以便找回旧会话。
26. 作为开发者，我希望父目录和子目录同时存在时各自只展示自己的会话，以便避免重复。
27. 作为开发者，我希望多选项目和工作目录进行筛选，以便集中查看相关工作。
28. 作为开发者，我希望搜索会话标题、目录名和项目名，以便快速定位内容。
29. 作为开发者，我希望筛选结果保持当前分组方式，以便保持浏览结构。
30. 作为开发者，我希望清空筛选后恢复完整列表，以便重新查看所有目录。
31. 作为开发者，我希望筛选不改变新会话目录，以便创建行为始终由入口决定。
32. 作为开发者，我希望新建后被筛选挡住的会话自动可见，以便立即继续工作。
33. 作为开发者，我希望项目和目录的位置保持稳定，以便依靠位置找到常用模块。
34. 作为开发者，我希望拖动调整项目和目录顺序，以便按工作习惯组织入口。
35. 作为开发者，我希望两种分组视图中的目录顺序一致，以便切换时保持方向感。
36. 作为开发者，我希望组内会话按最近活跃排序，以便优先访问当前任务。
37. 作为开发者，我希望折叠项目和目录组，以便减少侧边栏占用。
38. 作为开发者，我希望关闭目录时保留文件和会话，以便安全整理侧边栏。
39. 作为开发者，我希望主动关闭的目录不会因历史发现而重新出现，以便保持整理结果。
40. 作为开发者，我希望重新添加同一路径后恢复历史会话，以便继续之前的工作。
41. 作为开发者，我希望重启后恢复目录、关闭记录、视图、顺序和折叠状态，以便延续使用习惯。
42. 作为开发者，我希望重启后清空搜索及筛选，以便不会误以为其他会话丢失。
43. 作为连接多个服务器的开发者，我希望各服务器独立保存侧边栏状态，以便不混用不同机器的路径。
44. 作为开发者，我希望目录不可用时仍能查看历史并看到提示，以便理解无法继续执行的原因。
45. 作为开发者，我希望不可用目录不会自动回退到 Git 根目录，以便避免在错误位置执行任务。
46. 作为开发者，我希望恢复原路径后继续旧会话，以便恢复原有工作环境。
47. 作为开发者，我希望选择新位置时只添加新目录，以便不将旧会话自动关联到不同内容。

## Implementation Decisions

- 复用现有项目身份、会话身份及 Location 表达工作目录的能力。项目身份不等于会话工作目录；不为每个子模块创建新的 Git 项目身份。
- 保留原始目录选择贯穿目录添加、新会话草稿、Local 目标解析和最终会话创建。实际会话目录、文件浏览目录和文件候选搜索目录必须一致。
- 分组依据会话记录的实际工作目录，不依据标题、当前筛选或目录包含关系推断。父子目录会话分别归组，每个会话只出现一次。
- 目录视图为“工作目录 → 会话”；项目视图为“项目 → 工作目录 → 会话”。无 Git 目录在项目视图中独立成组。同名目录展示项目或路径提示。
- 目录入口、主动关闭记录及侧边栏展示状态优先由客户端管理。主动添加的空目录保留；历史会话目录可自动发现；主动关闭记录优先于历史发现。
- “添加目录”支持系统文件夹选择器和已知项目内浏览，确认前显示完整路径；不自动扫描 Maven 模块。
- 目录级新建直接选择该目录；项目级新建先选择该项目下的工作目录。全局新建依次使用当前会话目录、上次使用的目录，均不存在时要求选择。发送首条消息前显示目录并允许修改。
- 归属筛选支持多选项目和工作目录；名称搜索覆盖会话标题、目录名及项目名，结果保留当前分组结构。筛选只影响展示，不改变创建目录。
- 创建成功后，若当前筛选使新会话不可见，则清空筛选；展开所在分组，使新会话可见。
- 项目和目录默认按添加顺序排列，支持拖动；会话活动仅改变组内会话的最近活跃排序。项目视图在项目内沿用目录视图中的相对目录顺序。
- 按服务器分别持久保存已添加目录、关闭记录、视图、排序及折叠状态。搜索和归属筛选属于临时状态，应用重启后清空。
- “关闭目录”隐藏入口，保留文件和历史会话，并明确说明历史保留。重新添加同一路径恢复会话展示。
- 不可用目录保留分组及历史入口，显示“目录不可用”。创建或继续执行前要求恢复路径或选择新位置，不自动回退到仓库根目录。新位置只添加目录，不迁移旧会话。
- 工作目录只规定默认范围，跨模块访问继续遵循现有权限；不引入子树沙箱。
- 按仓库实验性行为和功能开关规范交付新样式及新默认行为。原有平铺视图继续可用。
- 当前后端已具备子目录会话表达能力，规格不预设新增公共 API 或数据库结构；若实现确需调整公共契约，遵循仓库代码生成和兼容规则。

## Testing Decisions

- 用户已确认以真实应用端到端流程作为主要测试边界。现有应用 E2E 使用 Playwright 驱动真实页面，API 由每页独立的内存服务器模拟；复用该设施验证界面行为、请求目标及客户端持久化。用真实后端和隔离临时目录补充验证实际目录保存、文件搜索及目录不可用行为，避免把模拟请求断言当成真实后端证明。
- 好的测试从用户操作开始，断言可见结果及实际持久记录；不复制分组、排序或目录解析的实现逻辑，不以组件内部状态作为主要断言。
- 使用同一 Git 仓库中的两个子模块和根目录、同名目录、无 Git 目录及空目录作为隔离 fixture。模块内外放置可区分文件，以验证搜索实际范围。
- 主流程覆盖添加子目录、发送前确认目录、创建会话、验证后端实际记录、目录和项目分组切换、文件浏览及 `@` 文件候选范围。
- 目录生命周期覆盖空目录保留、历史目录发现、父子目录不重复、关闭后重载不复现、重新添加恢复历史且磁盘文件未删除。
- 展示流程覆盖名称搜索、多选归属筛选、清空恢复、筛选不影响新建位置、新建后保证可见、组内活跃排序及分组位置稳定。
- 持久化流程通过真实重载验证长期状态恢复、临时筛选清空，并用独立服务器验证状态隔离。
- 不可用目录流程保留历史查看能力，验证创建和继续执行受阻且无根目录回退；恢复原路径后可继续，添加新位置不修改旧会话位置。
- Git 归属和现有跨模块权限按实际后端行为验证，避免将默认范围误当成权限边界。
- 系统原生文件夹选择器另做桌面实机验证。自动化应用测试覆盖目录选择结果进入应用后的完整流程，不以原生对话框自动化作为主流程前提。
- 复用现有工作区测试 fixture、目录选择器、会话创建回调、文件搜索回调、多服务器模拟和浏览器存储初始化设施。已有新会话用例可以在请求边界断言创建目录，目录选择器用例覆盖选择与失败重试，Home 用例覆盖关闭与重新发现项目，设置和标签页用例覆盖刷新及跨服务器路由。将新增契约放入对应产品区域的现有测试集合，避免建立重复覆盖所有区域的大型套件。
- 已有 composer 组件测试负责文件候选加载和菜单结果更新；应用 E2E 补充目录与服务器身份是否正确，不重复菜单内部行为断言。
- 内存 API 测试不访问真实磁盘，不能证明路径规范化、磁盘权限、后端持久化或真实文件检索。刷新只证明客户端重新加载；桌面重启后的恢复及原生目录选择仍需实机验证。
- 实现阶段遵循仓库测试技能要求，在对应包目录运行测试，并执行规定的类型检查及完整检查。实现阶段的测试结果与未验证项记录在 [acceptance.md](acceptance.md)。

## Out of Scope

- 自动扫描或发现 Maven 子模块。
- 根据会话标题推断工作目录，或自动迁移历史会话。
- 禁止工作目录之外访问的权限沙箱。
- 搜索会话正文。
- 自动迁移移动目录对应的旧会话。
- 自动将整仓源码加入模型上下文。
