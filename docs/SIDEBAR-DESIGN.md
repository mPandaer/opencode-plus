# 桌面侧边栏：项目与工作目录分组

状态：产品范围已确认，实现已集成至 `desktop-directory-groups`。最终自动化证据及未完成的实机验收见 [acceptance.md](../.scratch/desktop-sidebar/acceptance.md)。

本文记录需求访谈 Q1–Q16 的结论。领域术语见 [GLOSSARY.md](../GLOSSARY.md)。

## 目标

在 Maven 等多模块仓库中，用户可以把独立子模块作为工作目录，清楚看到会话属于哪个目录，并直接在该目录创建会话。打开子目录后，默认文件操作和 `@` 文件搜索应保留子目录范围。

例如 `mall/order-service` 和 `mall/payment-service` 共享 Git 项目 `mall`，但具有各自的会话工作目录。

## 设计决策树

- 会话归属：实际工作目录与 Git 项目身份分开（Q1）。
  - 默认文件浏览、工具操作与 `@` 搜索使用工作目录。
  - Git 操作继续识别外层仓库。
  - 允许按现有权限跨目录访问，不新增子树隔离（Q5）。
  - 历史会话按真实工作目录归组，不推测、不迁移（Q8）。
  - 父子目录分别归组，不重复汇总会话（Q9）。
- 侧边栏：保留平铺视图，新增分组样式，目录视图优先（Q2）。
  - 目录视图：工作目录 → 会话（Q4）。
  - 项目视图：项目 → 工作目录 → 会话（Q4）。
  - 项目、目录多选筛选，加名称搜索（Q6）。
  - 分组顺序稳定且可拖动，会话按最近活跃排序（Q13）。
- 工作目录入口：主动添加，空目录保留，不扫描 Maven 模块（Q3）。
  - 系统文件夹选择器或已知项目内浏览（Q11）。
  - 新会话目录由创建入口决定（Q7）。
  - 关闭目录只隐藏入口，重新添加恢复（Q10）。
  - 不可用目录保留历史入口，不回退到仓库根目录（Q15）。
- 状态：按连接的服务器分别保存长期侧边栏状态（Q12）。
  - 临时搜索和筛选在重启后清空。
  - 筛选不改变创建目录；创建后确保新会话可见（Q14）。
- 完整范围经用户确认（Q16）。

## 领域关系与约束

一个 Git 项目可以包含多个工作目录；一个工作目录可以包含多个会话。会话在侧边栏只归属其真实记录的工作目录，不因目录包含关系重复出现。

侧边栏目录记录属于客户端展示状态，不是新的后端项目或会话。目录组可由主动添加或历史会话发现而来；主动关闭记录优先于历史发现，直到用户重新添加该目录。

工作目录是默认操作范围，不是权限边界。用户选择子模块时，工具仍可按现有权限访问父级配置或兄弟模块。

同名目录必须通过所属项目或路径提示区分。没有 Git 的工作目录在项目视图中独立成组。

## 视图和交互

### 分组与排序

目录视图直接显示工作目录及其会话。项目视图增加项目父级，并允许项目和目录分别折叠。

项目和工作目录默认按添加顺序排列，支持拖动调整。两种视图使用一致的工作目录顺序：项目视图在对应项目内沿用该顺序。组内会话按最近活跃排序；会话活动不改变目录的位置。

### 添加目录

提供系统文件夹选择器，以及选择已知项目后浏览子目录的入口。确认前显示完整路径，提交后保留实际选中的目录。添加仓库根目录不自动扫描或添加子模块。暂时没有会话的已添加目录仍然显示。

历史会话对应的未添加目录自动展示；明确关闭过的目录除外。

### 新建会话

| 入口 | 目录规则 |
| --- | --- |
| 目录旁的“＋” | 使用该目录 |
| 项目旁的“＋” | 先选择该项目下的工作目录 |
| 全局新建，存在当前会话 | 使用当前会话目录 |
| 全局新建，无当前会话 | 使用上次使用的目录 |
| 首次使用，无可用默认目录 | 要求选择目录 |

发送首条消息前明确显示工作目录，并允许修改。选择子模块后，新会话提交使用该子模块目录，不因 Local 目标解析回退到 Git checkout 根目录。

### 筛选与搜索

支持多选项目和工作目录，文本搜索匹配会话标题、目录名和项目名。结果沿用当前分组方式。清空筛选恢复完整列表。

筛选只影响展示。例如当前会话属于订单模块，即使筛选为支付模块，全局新建仍遵循当前会话目录规则。点击支付模块旁的“＋”则直接使用支付模块目录。

创建成功后，如果新会话被当前筛选隐藏，清空筛选，并展开新会话所在组，保证可见。

### 关闭与恢复

操作名称为“关闭目录”，说明会话仍会保留。关闭不删除磁盘文件或历史会话。该目录保持隐藏，不因再次发现历史会话自动出现。重新添加同一路径时恢复其历史会话。

### 目录不可用

目录移动、删除或磁盘不可用时，保留分组和历史入口，标记“目录不可用”。在该目录创建或继续执行前提示恢复原路径或选择新位置，不自动改用 Git 根目录。

第一版选择新位置仅添加新目录，不迁移旧会话工作目录。恢复原路径后，旧会话可继续使用。

## 状态保存

| 状态 | 生命周期 | 范围 |
| --- | --- | --- |
| 已添加目录、主动关闭记录 | 重启后恢复 | 按服务器分别保存 |
| 视图选择、项目和目录顺序、折叠状态 | 重启后恢复 | 按服务器分别保存 |
| 搜索文字、多选筛选 | 本次使用，重启清空 | 当前服务器视图 |

连接另一台服务器时展示其自己的目录和状态；切回原服务器恢复原来的侧边栏，不混用两台机器的路径。

## 当前实现事实与修改方向

以下是访谈时对当前工作区的只读检查结论，描述现状而非已交付行为。

- 现有侧边栏配置为 `list` 和 `projects`，默认 `list`；Projects 按项目的 worktree 分组，尚无工作目录层。入口见 [settings/model.tsx](../packages/app/src/settings/model.tsx)、[sidebar-organized.tsx](../packages/app/src/shell/titlebar/sidebar-organized.tsx)。
- 后端 Location 可以保留子目录，会话独立记录 Location 和项目归属，具备表达子模块目录的基础。见 [location.ts](../packages/core/src/location.ts)、[session.ts](../packages/core/src/session.ts)。
- Home 添加项目后使用返回项目的 worktree，丢失原始子目录选择。见 [home/model.ts](../packages/app/src/home/model.ts)、[home/machine.ts](../packages/app/src/home/machine.ts)。
- 新会话 Local 路径优先使用主 checkout；需要保留选中的工作目录。见 [workspace/controller.ts](../packages/app/src/new-session/workspace/controller.ts)、[composer-adapter.ts](../packages/app/src/new-session/composer-adapter.ts)。
- `@` 搜索以实际 Location.directory 为根，修复目录传递即可保留子模块的默认检索范围。见 [filesystem/search.ts](../packages/core/src/filesystem/search.ts)。
- Git 根目录不会自动将整仓源码装入模型上下文。实际上下文由指引、会话消息和工具读取等共同决定；工作目录与仓库根目录都可能出现在环境信息中。见 [session/context.ts](../packages/core/src/session/context.ts)、[instructions/builtins.ts](../packages/core/src/instructions/builtins.ts)。

实现时复用现有项目和会话身份，优先将目录入口、关闭记录及展示状态留在客户端。新增默认行为按仓库实验性与 feature flag 规则交付；不改变服务器既有的权限边界。

## 验收场景

1. 在同一 Maven 仓库添加订单和支付两个子模块。目录视图显示两个组，项目视图显示共同项目下的两个目录组。
2. 从订单模块旁新建会话，首条消息发送前显示订单目录；创建后会话实际目录、文件浏览和 `@` 候选范围均为订单模块。
3. 添加仓库根目录后，根目录会话与子模块会话分开，每个会话只显示一次。旧根目录会话不被重新归到某个模块。
4. 添加一个空目录并重启，入口仍在；未明确添加的其他 Maven 模块不被扫描加入。
5. 同名工作目录通过项目或路径可区分；无 Git 目录可以添加、创建会话并显示在两种分组视图。
6. 搜索会话标题、目录名或项目名并组合归属筛选，结果维持当前分组方式，清空后恢复列表。
7. 筛选支付模块时，从当前订单会话使用全局新建，仍默认订单目录；创建后清空阻挡它的筛选并展开所在组。
8. 关闭订单目录，不删除文件和历史；重新加载不会因历史发现恢复它，重新添加才恢复。
9. 调整目录顺序并折叠分组，重启后恢复；搜索文字和筛选条件清空。切换服务器时目录和布局各自独立。
10. 会话活动仅改变组内会话顺序，不使目录组跳动；切换分组方式后目录相对顺序一致。
11. 工作目录不存在时显示不可用，历史仍可查看，创建和继续执行不回退到仓库根目录；添加新位置不迁移旧会话。
12. 在子模块会话中按现有权限读取父级配置或公共模块，确认默认工作目录与访问权限没有被混为一谈。
