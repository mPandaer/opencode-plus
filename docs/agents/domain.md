# Domain Docs

This repository uses a single-context domain documentation layout.

## Before exploring domain behavior

Read the root GLOSSARY.md and any relevant decisions under docs/adr/.
If either is absent, continue; create domain documents when terms or
decisions are resolved.

## Vocabulary

Use the glossary's canonical terms in specs, tickets, code discussions,
and tests. Resolve conflicting meanings before introducing a synonym.

## Decisions

Surface conflicts with existing ADRs explicitly.
Create ADRs only for decisions that are costly to reverse, surprising
without context, and based on a real trade-off.
